# 技术设计

## 设计原则

- 一个适配器只负责一个来源协议；
- 下载、解析、计算和序列化分开；
- 计算函数接收内存数据并返回普通对象，不自行访问网络；
- 写文件使用临时文件替换，避免中途生成损坏 JSON；
- 生产更新默认严格，诊断模式必须显式开启；
- 没有来源或权利记录的数据不能进入前端。

## Python 模块

### `scripts/harvest.py`

负责来源访问、数据编排和 JSON 数据契约。主要来源包括：

- FRED 官方 JSON API；
- OFR 官方金融压力数据；
- CFTC 官方报告；
- SEC EDGAR 官方接口；
- NBER 官方周期日期；
- Wikipedia 当前 S&P 500 表格及其修订信息；
- 经登记的价格、指数和波动率研究输入。

适配器必须设置超时、验证状态码、检查响应结构，并把错误转成结构化失败记录。

### `scripts/index_statistics.py`

只包含指数历史的纯计算：

- 年度回报；
- 牛熊周期；
- 极端交易日；
- 回报分布；
- 持有期结果；
- 滚动年化回报；
- 年内最大回撤；
- 月份季节性；
- 历史回撤和实现波动率。

输入是带日期索引的价格序列。函数不读取环境变量、不访问网络、不写文件。

### `scripts/macro_indicators.py`

负责跨序列宏观指标。目前包括使用 FRED Z.1 最新修订序列计算股票配置占比。所有输入
必须先按共同日期取交集，结果标明为 latest-vintage，不得用于声称严格时点回测。

### `scripts/update.py`

提供 `daily`、`weekly` 和 `full` 三个入口，管理更新前快照、失败回滚、审计和哈希链。

### 信任层

- `scripts/audit.py`：验证 JSON、时间排序、数组长度、最低覆盖和成分变更事件；
- `scripts/dataset_rights.py`：验证所有数据文件都恰好登记一次；
- `scripts/license_gate.py`：验证发布审查和数据登记；
- `scripts/chain.py`：对整套数据内容计算并验证链式摘要。

哈希链用于检测仓库中的数据快照变化，不等同于第三方时间戳服务或法律存证。

## 数据契约

生成对象的通用结构：

```json
{
  "_license": "repository notice",
  "_provenance": {
    "schema_version": 1,
    "generated_at": "2026-07-27T00:00:00Z",
    "generator": "scripts.harvest",
    "dataset_group": "fred-macro",
    "source_ids": ["fred"],
    "rights": {}
  },
  "dates": ["2026-07-25"],
  "values": [1.23],
  "unit": "percent"
}
```

具体数据集可以包含多个命名序列，但同一组 `dates` 下的并行数组必须等长、按日期升序且
无重复。JSON 不允许出现 `NaN` 或无穷值。

## 来源规则

### FRED

只使用官方 `series/observations` JSON API。必须提供 `FRED_API_KEY`。响应值 `"."` 视为
缺失，转换后按时间排序并去重。每个公开序列还必须登记原始发布者、频率、单位和
latest-vintage 限制。

### SEC

请求头必须包含 `SEC_IDENTITY`，格式为应用名称和真实联系邮箱。客户端速率保持低于
SEC 公布的公平访问上限。Form 4 和 13F 当前是可选内部数据，不因采集成功自动公开。

### CFTC

保存报告日期、观察时间和来源链接。当前快照可以支持从开始保存之后的时点研究；它不能
凭空恢复过去每个发布日期当时的完整版本。

### Wikipedia

当前成分和成分变更保留页面修订 ID、永久链接、抓取时间和 CC BY-SA 4.0 声明。当前成分
只能代表抓取日横截面，不能倒推出历史时点成分。

## 前端数据同步

Astro 构建前执行同步脚本：

1. 读取公开白名单；
2. 与数据集登记交叉验证；
3. 清空旧的生成副本；
4. 复制允许公开的文件；
5. 移除内部许可和审计字段；
6. 检查图表目录锚点与数据文件覆盖；
7. 生成静态页面。

`astro/public/data/` 是生成目录，不是数据源。权威数据始终位于根目录 `data/`。

## 测试策略

- 单元测试覆盖解析器、统计计算、边界值和失败回滚；
- 数据审计覆盖实际仓库 JSON；
- `ruff` 检查 Python 规范；
- `ty` 检查 Python 类型；
- `astro check` 检查组件和模板；
- `oxlint` 检查前端脚本；
- 生产构建验证所有路由、数据同步和目录锚点。

外部服务不稳定性通过边界 mock 测试，纯计算不 mock。
