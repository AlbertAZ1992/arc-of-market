# ArcOfMarket 产品架构改造总结

日期：2026-07-29

## 这次解决了什么

网站原来更像图表目录：数据不少，但首页不能快速说明今天发生了什么，研究页也没有稳定地把
图表和解释连起来。付费信号虽然有数据文件，却缺少明确的公开边界。

这次改造没有调整字体、颜色和整体视觉语言，重点重做了内容组织、图表表达和信号产品结构。

## 架构变化

| 层 | 现在负责什么 | 直接结果 |
|---|---|---|
| 数据层 | 保存市场数据与内部策略输出 | 公开图表和付费信号使用不同发布权限 |
| `chart-index.ts` | 定义图表数据、标题、来源和路由 | 图表配置不再散落在页面中 |
| `chart-facts.ts` | 从最新数据生成日期、数值和区间事实 | 图下解释不会只剩通用读图方法 |
| `schemas/*.json` | 定义章节顺序、图表和组件引用 | 调整页面结构不用重写页面组件 |
| `prose/*.json` | 保存标题、解释、意义和变化条件 | 改文字不用改渲染代码 |
| `ResearchPage.astro` | 按 schema 统一渲染研究页 | 五个市场页面使用同一内容规则 |

页面 schema 会检查重复章节、错误图表引用、缺失文案和非法组件。错误配置会在构建时失败，
不会等到上线后才变成空白模块。

## 首页现在表达什么

首页先给市场分化，再把判断拆成证据：

1. S&P 500、Nasdaq-100、道指和七巨头等权指数的一年归一化走势；
2. 道指与 QQQ 的 20 日回报差，说明蓝筹和科技是否同向；
3. 标普与纳指 50 日广度和历史分位，说明上涨由多少公司参与；
4. VIX 期限结构与 OFR 金融压力，说明价格回撤是否扩散成系统压力；
5. 股票配置、收益率曲线、年内回撤和长期均值，把今天放回历史。

因此首页不是品牌介绍页，也不是只放一张标普走势图。用户能在首屏附近看到数字、图表、
判断依据和继续阅读入口。

## 每张图怎样形成叙事

研究页不再先解释“这张图用于观察什么”，而是按固定顺序回答：

- **结论句**：直接说图中最重要的变化；
- **数据证据**：构建时读取最新文件，写出日期、数值、区间或极值；
- **历史参照**：给出长期均值、历史分位、最佳或最差时期；
- **今天的含义**：说明这组事实怎样改变当前判断；
- **继续观察**：明确哪些后续变化会加强或推翻判断；
- **来源与限制**：写清口径、代理指标和不能推出的结论。

有数据文件的图表必须生成至少一条含日期或数字的事实，否则构建失败。没有数据支持的结论
不写，尚未取得可靠来源的数据不造占位值。

## 信号如何产生付费价值

免费层公开：

- 四项策略的名称、计划观察维度和计划更新频率；
- 当前可用数据区间与日度数据数量；
- 当前验证阶段；
- 付费字段的名称。

付费层保留：

- 当前方向；
- 目标仓位；
- 下一触发；
- 失效条件；
- 状态变更原因与提醒。

`regime_rotation.json`、`rs_leaders.json` 和 `breadth_pulse.json` 已改为内部策略数据，
构建流程不会把它们复制到公开网站目录。订阅开关仍为关闭，避免产品尚未完成验证时作出承诺。

## 相比竞品提升在哪里

| 对比维度 | History of Market / 同类图表库 | ArcOfMarket 现在的做法 |
|---|---|---|
| 数据覆盖 | 历史图表丰富 | 补齐主要缺口，并标明仍缺可靠来源的数据 |
| 阅读方式 | 以单张图和历史资料为主 | 图表后直接给事实、意义和判断变化条件 |
| 当前市场 | 用历史分位解释单项读数 | 首页把四类资产、广度、期限结构和金融压力串成当日判断 |
| 信号产品 | 单一指标或直接展示结果 | 免费层证明方法，付费层保留执行信息 |
| 更新架构 | 页面内容通常人工维护 | 数据、结构和文案分离，可分别自动更新 |

History of Market 最值得学习的是把事实写成连续段落：先给判断，再用数字和历史位置证明。ArcOfMarket
在此基础上增加跨资产的当日判断和付费执行边界。核心提升不是多写几段文字，而是让用户完成
三件事：先看到变化，再理解原因，最后知道什么数据会推翻当前判断。
